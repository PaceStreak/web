# PaceStreak Web

The public site for **[www.pacestreak.com](https://www.pacestreak.com)** — the
first thing a stranger sees. PaceStreak is a habit and streak tracker:
training, and anything else worth doing regularly. Keep each one weekly, watch
the grid fill. The product itself is live at
[app.pacestreak.com](https://app.pacestreak.com).

Astro and Tailwind CSS v4. Static output, no client framework, deployed on
Cloudflare Pages.

## Where this sits

| `app.pacestreak.com` | [`app`](https://github.com/PaceStreak/app) | The product. Requires an account. Not indexed. |
| `api.pacestreak.com` | [`api`](https://github.com/PaceStreak/api) | Backend. |
| `blog.pacestreak.com` | [`blog`](https://github.com/PaceStreak/blog) | Blog. |
| `status.pacestreak.com` | [`status`](https://github.com/PaceStreak/status) | Uptime, public. |

**This repository is the marketing site and stays that way.** The product is
built in [`app`](https://github.com/PaceStreak/app). The split is deliberate:
this site must never grow an auth dependency, so a product outage cannot take
down the page that explains the product. See
[ARCHITECTURE.md](./ARCHITECTURE.md).

## Layout

```text
src/pages/           index, features, streaks, social, security, about, faq,
                     changelog, privacy, terms, 404.
src/data/changelog.ts The /changelog entries.
src/data/product.ts  Every product claim. Numbers come from the api/app code;
                     change them there first, then here.
src/lib/chain.ts     Port of the streak rules for the /streaks simulator.
src/layouts/Base     Head, nav, footer. Every page goes through it.
src/components/      Seo, Nav (with a no-JS <details> mobile menu), Footer,
                     Faq, ActivityGrid.
src/data/faq.ts      One FAQ array. The landing page shows a subset, /faq shows
                     all of them, and the FAQPage structured data is generated
                     from it — so an answer cannot drift between the three.
src/styles/global.css Tailwind theme tokens + the few real components.
src/scripts/app.js   Builds the activity grid and counts the stats up.
public/_headers      Security headers + cache policy, applied by Cloudflare Pages.
public/_redirects    Vanity short links (/github, /blog, …).
check-html.py        Build guard. Runs in CI against dist/.
```

`404.astro` is not optional: without it Pages answers every unknown path with
`index.html` and a **200**. The sitemap is generated by `@astrojs/sitemap` at
build time — there is no checked-in `sitemap.xml` to keep in sync.

## Styling

Tailwind CSS v4, compiled through `@tailwindcss/vite`. **The play CDN is not
usable here** — it is a third-party script and the CSP is `default-src 'self'`,
so it would be blocked in production while working perfectly in local preview.

Design tokens live in one `@theme` block in `src/styles/global.css`. Tailwind
generates utilities from them, so `--color-accent` gives `bg-accent`,
`text-accent` and `border-accent` with no config file and no drift between a
token and its utility.

`@layer components` holds only what utilities are a poor fit for: the activity
grid, the buttons, the footer separators and the page gutter. If a rule there
could be three utility classes in the markup, it should be.

## Deploying

**Push to `main`. That is the whole process.** The Cloudflare Pages project is
connected to this repository via Cloudflare's GitHub integration and builds on
every push — there is no deploy workflow in this repo, and no API token to
manage.

Build settings, if they ever need re-entering:

| Setting | Value |
| --- | --- |
| Framework preset | Astro |
| Build command | `npm run build` |
| Build output directory | `dist` |

The Cloudflare Pages project is **`pacestreak-web`** (renamed from `pacestreak`;
its `pages.dev` hostname stayed `pacestreak.pages.dev`, so the two do not
match). Passing the wrong `--project-name` does not error — it creates a new
project.

Astro publishes only `dist/`, which contains what you put in `src/pages` and
`public/` — so repository source can no longer leak onto the origin the way it
did when the repo root was deployed directly.

To deploy by hand (you should not need to):

```bash
npm run build
npx wrangler pages deploy dist --project-name=pacestreak-web
```

**Asset URLs are content-hashed by the build.** This used to be a hand-rolled
script that had to be remembered, and forgetting it once shipped new markup
against a four-hour-old cached stylesheet. Astro does it natively; that whole
failure mode is gone.

**`assetsInlineLimit: 0` in `astro.config.mjs` is load-bearing.** Vite inlines
assets under 4KB as `data:` URIs and Astro inlines small `<script>` blocks into
the HTML. The CSP in `public/_headers` is `script-src 'self'` with no
`'unsafe-inline'`, so either would be blocked by the browser — silently.
Setting the limit to 0 forces real, hashed files.

## Notes for anyone editing this

**No external requests, and no API calls.** No font CDN, no analytics, no
third-party scripts, and never a login, session check or call to
`api.pacestreak.com`: a product outage must not take this site down.
The Content-Security-Policy in `_headers` is `default-src 'self'` and will
block anything you add from elsewhere — that is deliberate, not an obstacle to
route around. If you add a dependency, vendor it.

**`Cache-Control: no-transform` in `_headers` is load-bearing.** Cloudflare
Web Analytics (now off) used to inject a beacon script that the CSP blocked;
the header keeps any future edge rewrite off the pages.

**`check-html.py` runs in CI and has earned its place.** It catches collapsed
whitespace around inline links (shipped three times: "or write tohello@"),
inline scripts, and `data:` URIs — all of which deploy without erroring. Its
separator rule is scoped to footer containers on purpose: a typed `·` is a bug
where CSS draws one and correct in prose.

**The page works without JavaScript, mostly.** The real stat numbers are in the
markup; `app.js` only animates them. The activity grid is the exception — it is
generated in JS, because 182 hand-written `<i>` elements is not a reasonable
thing to keep in the HTML.

**Grid cell colours are specificity-sensitive.** `.heat i` deliberately sets no
`background`. It would be specificity 0-1-1 and would beat the single-class
`.lvl--N` rules, flattening every cell to one colour. Paint cells only via the
level class.

**The activity grid's columns are the definite axis.** `grid-template-rows:
repeat(7, 1fr)` sizes rows from the container height, while `aspect-ratio: 1`
cells size the container height from the rows — circular, resolving to zero, so
the hero renders an empty card with no error anywhere. Columns get `1fr`; rows
follow from the aspect ratio.

**The grid's fade-in uses `backwards`, not `forwards`.** With `forwards` the
squares depend on the animation running to become visible, so when the
`@keyframes` went missing during a restyle every square stayed at `opacity: 0`.
The settled state must be correct without the animation.

**Watch `padding` shorthands inside `.wrap`.** A shorthand resets
`padding-inline` to 0 and collapses the page gutter on mobile. Use
`padding-block`. This has bitten twice.

**Motion is opt-out.** Everything animated is behind
`prefers-reduced-motion`, and the settled state is the correct one — that is
also the easiest way to screenshot the page.

**Contrast is a review criterion.** Muted greys that look fine routinely
measure around 4.0:1 and fail WCAG AA. Measure against the actual background,
including cards, not just the page background.

## Domain

`www.pacestreak.com` is canonical; the apex `pacestreak.com` 301-redirects to
it. Both are custom domains on the Pages project, and Cloudflare issues a
**separate certificate per hostname** — they are not one cert with two SANs, so
both expiries are monitored independently at
[status.pacestreak.com](https://status.pacestreak.com).

Keep the apex attached to the Pages project even though it redirects: the
redirect rule runs first, but if it is ever deleted the apex falls back to
serving the site rather than returning a 522.
